# COBOL Application Test Plan

The following test plan is designed to validate the current business logic and implementation of the COBOL account-management sample with business stakeholders. It is structured as a reusable validation matrix for later conversion into unit and integration tests in a Node.js application.

| Test Case ID | Test Case Description                                                                 | Pre-conditions                                                                            | Test Steps                                                                                         | Expected Result                                                                                                                                                       | Actual Result                                | Status (Pass/Fail) | Comments                                                                                   |
| ------------ | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------ |
| TC-001       | Application starts and displays the main menu                                         | COBOL app is compiled and run from the project root                                       | 1. Execute `./accountsystem` 2. Observe the opening screen                                         | The system shows the account menu with options `1. View Balance`, `2. Credit Account`, `3. Debit Account`, and `4. Exit`                                              | To be recorded during stakeholder validation | Pending            | Confirms the main entry point is interactive and user-driven                               |
| TC-002       | Invalid menu choice is rejected                                                       | App is running and menu is displayed                                                      | 1. Select an unsupported option such as `9` 2. Review the response                                 | The system displays `Invalid choice, please select 1-4.` and returns to the menu loop                                                                                 | To be recorded during stakeholder validation | Pending            | Verifies menu validation behavior                                                          |
| TC-003       | View balance shows the current account balance                                        | App is running and the system is at the initial state                                     | 1. Choose option `1` from the menu                                                                 | The system reads the stored balance and displays the current balance as `1000.00`                                                                                     | To be recorded during stakeholder validation | Pending            | Validates the default opening balance and the `TOTAL` operation                            |
| TC-004       | Credit operation increases the balance                                                | App is running and account balance is at the default value of `1000.00`                   | 1. Choose option `2` 2. Enter a credit amount such as `250.00` 3. Observe the program output       | The system prompts for a credit amount, reads the balance, adds the amount, writes the new balance, and displays the updated value `1250.00`                          | To be recorded during stakeholder validation | Pending            | Covers the positive-addition business rule                                                 |

Choose option `3` 2. Enter a debit amount such as `200.00` 3. | TC-007       | Balance remains unchanged after a failed debit attempt                                | App is running and the balance has been set to the default value or any known prior value | 1. Immediately choose `1` to view the balance | The displayed balance remains the same as before the failed debit attempt                                                                                             | To be recorded during stakeholder validation | Pending            | Ensures rejected transactions do not mutate stored state                                   |

Choose option `4`                                                                               | The program displays `Exiting the program. | TC-009       | Data flow between menu, operation, and storage layer works for a full credit scenario | App is running from a fresh start                                                         | 1. Choose option `2` 2. Enter `250.00` 3. Choose option `1` 4. | TC-010       | Data flow between menu, operation, and storage layer works for a full debit scenario  | App is running from a known balance state that can cover the debit amount                 | 1. Review the displayed balance                              | The value displayed is `1000.00`                                                                                                                                      | To be recorded during stakeholder validation | Pending            | Establishes the canonical starting balance for stakeholder sign-off                        |
